# Ethics and Limitations

## Purpose boundary

MedRisk Audit Lab is a research, education, and portfolio project. It is
**not a medical device** and provides no clinical value: no diagnosis, no
treatment recommendations, no triage, no decisions about real patients.
Every user-facing surface (README, demo UI, LLM outputs) repeats this
boundary.

## Data ethics

- The dataset (UCI "Diabetes 130-US Hospitals", CC BY 4.0) is public and
  de-identified; no real patient can be re-identified from anything this
  project stores or publishes. No real patient data is ever accepted as
  input.
- **Era limit:** the data describes US hospitals between 1999 and 2008.
  Clinical practice, coding, medications, and populations have changed;
  nothing here generalizes to current care, and in particular nothing
  transfers to present-day Japanese healthcare.
- **Label limit:** "no readmission" includes readmissions to other
  hospital systems, post-discharge deaths, and loss to follow-up. Measured
  performance therefore reflects incomplete outcome capture.
- **Temporal limit:** the data has no timestamps, so no past→future
  validation is possible; patient-level random splits are the strongest
  available design and this is stated wherever results appear.

## Fairness ethics

- Subgroup analysis over `race`, `gender`, and `age` is an **observational
  audit**, not a fairness guarantee. Missing or unknown demographic values
  are reported as their own groups and never imputed or guessed.
- Groups under 50 patients are labeled "insufficient sample for
  conclusions"; the project makes no claim — positive or negative — about
  them.
- Bracketed age, coarse race categories, and a near-empty gender category
  limit what the audit can see; intersectional analysis was not performed
  (sample sizes would be misleadingly small).
- Equal AUROC across groups does not imply the model is harmless: harms
  depend on deployment context, thresholds, and base rates, none of which
  exist in a portfolio setting.

## Explanation ethics

- SHAP values are **model attributions on this dataset, not causal or
  clinical evidence**. The wording is enforced in the Model Card, the UI,
  and the LLM prompt contract, and validators reject LLM text that
  presents attributions as medicine.
- The LLM is an explanation component under a strict contract; it is
  evaluated quantitatively and its failure examples are published. The
  stored demo outputs are generated by a deterministic stub and are
  labeled as such — no output in this repository came from a live LLM.

## Abstention ethics

The system prefers "no reliable prediction" over a confident guess inside
its uncertainty band. The coverage/performance trade-off is published; in
any real setting that trade-off would be a clinical governance decision,
not an engineering one.

## Honest-reporting commitments

- The final test set was evaluated exactly once, with every setting frozen
  beforehand; the run manifest records it.
- Reported performance is moderate (final-test AUROC 0.688) and is
  presented as such; no metric was improved by weakening evaluation
  validity.
- Known failure cases (misclassifications, LLM violations) are published
  alongside successes.
